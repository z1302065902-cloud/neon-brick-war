## 四、已实现清单

**玩法**
- 十关战役，每关 3 个据点 A→B→C，末位出 Boss，清关后 **2.4 秒自动进下一关**
- **6 把枪**，各有独立数值、曳光颜色、合成音色、**积木枪型**
- **武器合成**（F）：三条数据驱动配方，合成消耗两把零件枪
  - 脉冲 + 轨道 → 针刺驱动器（穿盾、可贯穿 2 个身体）
  - 散射 + 榴弹 → 破片爆裂者（每颗弹丸都爆炸）
  - 电弧 + 等离子 → 风暴核心（链式 5 段 + 3.4m 爆炸）
- **机体重建**（G）：击杀积累**废料**，够数后打散重组成新机体
  - 标准 / 侦察（6 废料，快脆）/ 重装（14，慢厚）/ 游走（24，高跳）
  - 机体改变**体型轮廓**而非配色 —— 侦察更瘦腿更长、重装更宽更矮
- **3 个各不相同的 Boss**：装甲装卸机（正面免伤、蓄力冲锋）/ 无人机母舰（悬浮、远程、召唤僚机）/ 核心守卫（弱点周期性开窗）
- **飞行敌人**：积木鸟，9m 半径 4.2m 高度环绕，俯冲攻击后拉起
- **9 种道具**、跳跃、多层高台

**表现**
- 积木打散（死亡碎成 22 块）与聚拢（复活/重建时砖块汇聚成形）
- 关节骨架步态动画，步频由刚体实际速度推导，不会脚底打滑
- 画布内游戏 HUD，布局全部由视口推导（四设备各 50 局验证零重叠）
- 泛光 + 阴影 + 地面网格 + 积木背景城市（合并成 2 个 draw call）
- 每关独立光影色彩分级（曝光 / 雾距 / 主光色调 / 补光 / 泛光强度）

**系统**
- 中英双语，所有面向玩家的文本走 `t([en, zh], lang)`
- 全合成音频，零音频资源；十关各一首 BGM（BPM/调性/音阶由关数派生）
- 真暂停、音量控制、静音
- 双 build 付费门闸（前 5 关免费）

## 五、下一步待办

1. **十关仍是同一套竞技场骨架** —— 每关有独立配色、布局、建筑高度、多层高台和光影分级，但地形结构是同一套模板。做成真正不同的地形（吊车甲板 / 天桥 / 冷却厅）是纯设计工作量
2. **额外关卡的差异化机制** —— 目前十关只有数值和配色递进，没有关卡专属机制（如限时、护送、防守）
3. 打磨：Boss 弱点判定与胶囊容差仍是两套逻辑（长距离射击时观感可能不一致）

## 六、反复踩过的坑（重要）

### Rapier / 物理
- **绝不能用 `removeRigidBody` 处理尸体** —— 会让 `body` 变成悬空 WASM 句柄，之后任何 `body.translation()` 让 Rapier **直接崩溃**（`wasm unreachable`，不是 JS 异常）。正确做法是刚体转 Fixed + 禁用碰撞体（"冻结"）
- **`castRay` 的 `solid: true`** 在射线起点位于碰撞体内部时返回 toi=0。做遮挡检测必须用 `solid: false` + `filterPredicate` 排除射手和目标本体
- **射线武器要排除目标自己的碰撞体**，否则瞄得越准越打不中（这 bug 存在很久）
- **贯穿武器要把已穿透的身体从遮挡集合里移除**，否则第一个敌人挡住到第二个的视线
- **飞行/悬浮单位用 `setTranslation` 直接写 Y**，别靠施力

### 参数污染（这个项目最反复出现的一类 bug）
- `setLinearDamping(6)` 是为地面防滑调的，但同时作用在 Y 轴，把跳跃冲量吃掉了大半
- `clampBounds` 是水平求解，却把 0.22m 的台阶当墙推开，导致楼梯完全不可用
- 刷怪公式 `3 + index + (mapIndex - 1)` 是关卡序号改 0 基之前写的，少刷一个敌人

**教训：改一个参数的用途时，先搜它还在哪些地方被消费。**

### 测试环境
- **测试环境没有指针锁定** → `updateEnemies` 早退、Boss 的 `update()` 不跑。测 Boss 要手动驱动 `boss.update(dt, ctx)`
- **解锁指针会触发暂停**（真暂停功能），测移动前必须 `g.input.pointerLocked = true`
- **敌人放到竞技场外（|x| 或 |z| > 28）会掉下去**，坐标变负会让距离判定全废
- **连续 `setTranslation` 后立刻开火，broad-phase 还没更新**，射线会打空，中间要 `await` 一个物理帧
- **不要跨波次保留敌人引用** —— 清光一波会换波并释放旧刚体
- **断言要在改状态之前求值**
- CDP 的 `resize_page` 对多标签页常不生效，用 `emulate` 的 viewport 参数

### 构建
- **Linux 沙箱跑不了 `npm run build`**（node_modules 是 macOS 装的，缺 `rolldown-binding.linux-arm64-gnu.node`）。`npx tsc --noEmit` 正常。构建要在 macOS 上用终端驱动执行

## 七、运行时调试钩子

页面里 `window.__NEON_BRICK__` 就是 `Game` 实例（TS private 在运行时可访问）：

```js
g.debugState                    // map/win/ready/advancing/paused
g.level.blocks                  // 关卡全部 AABB（台阶=薄而宽，高台支腿=细而方）
g.enemies / g.boss / g.pickups
g.salvage / g.chassis           // 废料数与当前机体
g.baseSpeed / g.baseJump        // 当前机体的实际移速与跳跃力
g.loadout.fusablePair()         // 当前可合成的配方
g.loadout.fuse(combo)           // 直接合成
g.loadout.atIndex(i)            // 第 i 个槽位的武器
g.player.setGun(id, c, body)    // 换枪型
g.physics.world.bodies.len()    // 泄漏检查
g.renderer.info.memory.geometries
g.hud.debugRects                // 上一帧真实绘制的矩形，HUD 布局回归用
g.debris.activeCount            // 活跃积木碎块数
g.tps._yaw                      // 相机偏航（只读 getter 是 yawRadians）
```

## 八、环境

- 项目路径：`~/Desktop/游戏项目/neon-brick-war`（不是 Desktop 根下的空目录 `lego-game`）
- 技术栈：Vite 8 + TypeScript 6 + Three.js 0.184 + Rapier3D 0.20
- **渲染引擎是 Three.js，这是有意的决定** —— 它是网页 3D 的最优解，换引擎等于把 6000 行推倒重来而画面不会更好。画面问题在光照和材质，不在引擎
- 发布包：`npm run build:demo` / `build:full`，产物 3.3 MB（gzip 1.26 MB），**sourcemap 默认关闭**（需要时 `VITE_SOURCEMAP=1`）
- 源码约 6000 行；备份在 `.backup-20260919/`（已 gitignore，git 到位后冗余）
